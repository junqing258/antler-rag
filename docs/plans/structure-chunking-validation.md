## 使用与运维

创建后配置固定。已有知识库切换结构策略需新建并重新上传。生产升级及全量重建必须停止全部写入者并备份完整数据目录，确认数据库符合当前 schema 后，运行 `--dry-run`，检查报告后才运行 `--confirm`。该确认命令删除整个活动 collection；失败后的残留向量需清理或恢复完整备份后才能恢复服务。成功索引后的图谱需管理员另行重建。

具体步骤与失败源文件处理见 [备份、恢复与升级](../operations/backup-and-upgrade.md)。

## 启动校验修复

2026-10-14：现有本地数据库已具备全部当前业务表和字段，但存在未使用的附加表及不同的 `chunk_strategy` 物理列位置。原校验误要求所有表完全相同、列顺序相同，导致 lifespan 启动失败。已改为校验所需表与每个业务表的列名集合，忽略物理顺序和无关附加表；缺少必需表/字段仍然拒绝。不读取版本记录，不转换或删除数据。

新增回归验证列顺序不同、附加表存在时，启动初始化和只读重建预检均可通过，并确认 schema 和原有记录不变。27 项 schema/索引服务相关测试通过。使用实际本地数据目录执行应用 lifespan 验证，启动和关闭均成功，向量库健康检查通过。
